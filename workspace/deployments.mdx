Taking your software live no longer requires waiting on a manual handover. Once Azotha has configured a deployment target for your project, your agent can carry out deployments for you: publishing the exact version you reviewed, reporting progress as it happens, and rolling back to the previous release if something looks wrong. You stay in control through approvals — the agent can only ever deploy to targets that Azotha has set up and you have signed off on.

## What Is a Deployment Target?

A deployment target is a pre-configured destination for your software — for example, the production environment where your team or customers use your application. Azotha's team defines each target for your project: where the software runs, how it is built and verified, and how it goes live.

Your agent can see which targets exist and deploy to them, but it cannot invent new destinations, change how a target works, or reach infrastructure outside what has been configured. If your business needs a new target — a staging environment, a second application, a different hosting setup — Azotha's team adds it for you.

Targets are not limited to software Azotha built from scratch. If your business already has an established deployment setup, Azotha's team can configure a target that plugs into that existing pipeline, so your agent deploys through the process you already trust.

## How a Deployment Works

When you tell your agent to deploy, it follows a controlled sequence from your instruction to verified live software.

<Steps>
  <Step title="You approve the release">
    After reviewing the result at your preview URL, you tell the agent to deploy. Deployments require your approval, and each approval is bound to a specific target and its exact configuration. If the target's configuration changes later, a fresh approval is required before the agent can deploy to it again.
  </Step>
  <Step title="The agent deploys the exact version you reviewed">
    The deployment is pinned to the precise version of your software that you signed off on — not "the latest changes." What goes live is exactly what you saw in your preview, with no untested work slipping in between review and release.
  </Step>
  <Step title="The build and release are verified">
    The target's configured build, test, and health checks run before the new release is activated. The agent monitors the deployment and reports its status — preparation, activation, and verification — so you always know where things stand.
  </Step>
  <Step title="Rollback is always available">
    Azotha keeps the previous successful release ready. If anything looks wrong after a deployment, the agent can roll back to that release and verify it is healthy again — a single instruction from you, no infrastructure work required.
  </Step>
</Steps>

## Directing a Deployment

You direct deployments the same way you direct any other agent task — in plain language.

```text
The version at the preview URL looks good. Deploy it to production.
```

```text
Something is off with the release from this afternoon.
Roll production back to the previous version.
```

The agent handles the technical sequence — selecting the approved target, deploying the pinned version, watching the checks, and confirming the outcome — and reports back when your software is live.

## Deployments That Survive Interruptions

Real deployments can take time — builds, checks, and activation do not always finish within a single conversation turn. Azotha treats every deployment as a durable job that runs to completion regardless of what happens in your session.

- **The agent waits and picks up automatically.** If a deployment is still running when the agent reaches the end of its working turn, your workspace shows that it is waiting on the deployment. Once the deployment finishes, the agent automatically resumes and reports the outcome — you do not need to prompt it again.
- **Interruptions do not lose deployments.** If the deployment service restarts mid-deployment, the job resumes from where it left off rather than starting over or silently failing.
- **No accidental double deployments.** Asking to deploy a version that is already deploying simply reconnects to the deployment in progress. Asking to deploy a different version while one is underway is reported as a conflict instead of launching a competing release.
- **Cancelling stays safe.** If you cancel a session, the agent stops following the deployment, but the deployment record itself is preserved so you can always see what happened.

Every status the agent reports includes what phase the deployment is in, whether it has finished, and what happens next — so you always know whether your software is live, still on its way, or needs attention.

<Tip>
  A successful deployment confirms that your software built, activated, and passed its health checks. It does not by itself prove that a specific feature behaves the way you asked. After a deployment, take a moment to verify the actual change in your live application, or ask the agent to check it for you.
</Tip>

## Built-In Safeguards

Agent deployments are designed so that convenience never comes at the cost of control.

- **Approved targets only.** The agent can deploy exclusively to targets Azotha has configured for your project. There is no way for it to deploy anywhere else.
- **Approvals tied to configuration.** Your approval covers a specific target exactly as it is configured. Any change to that configuration invalidates the approval, so nothing changes underneath you silently.
- **Exact-version pinning.** Every deployment publishes the precise version you reviewed. Re-deploying the version that is already live is safe and changes nothing.
- **Verified activation.** A release only becomes live after the target's configured checks pass.
- **One-step rollback.** The previous successful release is retained and can be restored and re-verified on request.

<Note>
  Deployment targets are set up by Azotha's team as part of taking your project live. If you are not sure whether your project has a target configured, or you need an additional one, contact the Azotha team.
</Note>
