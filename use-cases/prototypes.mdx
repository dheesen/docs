The most expensive mistake in software is building the wrong thing. A full build based on assumptions — about what users need, how they'll navigate, what data matters — can consume months and significant budget before anyone discovers the core premise was off. With Azotha, you can turn an idea into a working prototype quickly, put it in front of real users, and gather genuine feedback before committing to a larger investment. Test the idea first; build confidently after.

## What Can Be Prototyped?

Azotha agents can build a working prototype for a wide range of software concepts. If you can describe it in plain language, the agent can build a testable version of it:

- **Web app concept** — a multi-page application with real navigation, forms, and logic
- **Internal tool MVP** — a minimal version of a dashboard, admin panel, or workflow tool your team can actually use
- **Landing page with a form** — validate demand for a product or service before building the full thing
- **Dashboard with sample data** — see how your key metrics could be presented before connecting live data sources
- **Customer-facing workflow** — a step-by-step process your customers would move through, from intake to outcome
- **API integration proof of concept** — confirm that two systems can be connected and that the data exchange works as expected

## From Idea to Testable Prototype

<Steps>
  <Step title="Describe the problem and the user">
    Write a brief description of the problem you're solving and who would use the software. Focus on the need, not the technical solution. For example: "Small logistics companies need a simple way to track which drivers are assigned to which deliveries today."
  </Step>
  <Step title="Share reference material">
    If you have sketches, screenshots of similar products, reference URLs, or rough wireframes, share them with your agent. Visual references and examples of what you like (and don't like) help the agent make better decisions about layout, flow, and features.
  </Step>
  <Step title="Review the working prototype">
    The agent builds a working prototype and makes it available at your dedicated preview URL. You can interact with it, enter data, and navigate through it exactly as a real user would — because it is real, running software.
  </Step>
  <Step title="Gather feedback from real users">
    Share the preview URL with potential users — customers, colleagues, or anyone who represents the audience for this software. Watch how they use it, note where they hesitate or get confused, and collect their direct feedback.
  </Step>
  <Step title="Decide what to do next">
    Armed with real interaction data, make a clear decision: iterate on the current prototype, invest in building it further, or pivot to a different approach. Every outcome is a good one — you've learned something real at a fraction of the cost of a full build.
  </Step>
</Steps>
